# Case Studies

Deep-dives into how real-world production systems **and teams** are built, and
why. Each note analyses a specific company's engineering or organisational
approach, extracting the generalisable patterns behind it rather than treating it
as a one-off.

These differ from [Reading](../reading/) notes: a case study is a substantive
analysis of a specific company or system, not a one-line citation of an article.

## Notes

Grouped by what each case study is about.

### Frontend & performance

- [Linear's Performance Architecture](linear-performance-architecture.md) — how Linear achieves perceived speed by treating the browser as the database and the server as a sync target: local-first sync engine, optimistic updates, granular reactivity, and disciplined build/load/animation choices
- [ChatGPT's Web Performance Architecture](chatgpt-web-performance.md) — the architectural opposite of Linear, driven by serving ~1B anonymous users: streaming SSR, render-first, server-evaluated inlined flags, deferred imports until composer TTFI, prepaid bot defence, and "the network is the enemy" startup discipline
- [Vercel's Agent Loop for Instant Navigations](vercel-v0-instant-navigations.md) — an agent looping write-failing-test → fix → re-run over v0's slow routes, made possible by a framework-shipped `instant()` helper that turns "feels snappy" into a green-or-red oracle; the three requirements for an unattended loop, and the argument that frameworks matter *more* in the agent era because they can ship verifiers primitives cannot *(Vercel on its own product)*
- [Lovable's Migration Off Next.js](lovable-nextjs-migration.md) — a strangler-fig framework migration on a 42M-visitor site: proxy-worker routing with *framework stickiness* (whole route groups, so users never pay a ~5s hard navigation), portability enforced by lint rules, platform adapters and a CI portability check down to 3% framework-specific code, agents drafting the PRs, and a candid OOM incident where static JSON tipped a worker past the 128MB isolate limit *(Lovable migrating onto its own platform — the mechanism is checkable, the Next.js verdict is not disinterested)*

- [Linear's CI Rework Under Agent Volume](linear-ci-rework.md) — absorbing a near-quadrupled test suite (~2,000 tests added weekly) while PR wait fell from 6+ minutes to just over 5: setup overhead as the cap on parallelism (4→8 shards while total setup time *fell*), `node_modules` caching abandoned because rebuilding was faster (28→7.5s), and ~87,000 runner-minutes saved monthly by batching seven checks into two *(company-authored and self-reported, but no CI vendor named and the figures are per-stage)*

- [Rendering Huge Pull Requests (GitHub Copilot App)](github-huge-pr-rendering.md) — virtualisation split into two geometry domains because comments have no knowable height (markdown reflow, expandable blocks, async assets): deterministic code rows with all heights known before paint versus lazily measured blocks bounded to viewport ±2400px, height fingerprinting keyed to content hash *plus bucketed width* so ordinary resizes don't invalidate the cache, measurement moved off the scroll path, and an unattended autopilot reading the app's own rAF jank sampler. The deliberate opposite of ChatGPT's no-virtualisation choice

- [Anthropic's claude.ai Performance Sprint](anthropic-claude-ai-performance-sprint.md) — an agent-driven two-week sprint (3.1× geometric mean across thirteen measurements) whose transferable part is the *metric*: wall-clock time was too noisy to gate on, so CI gated on **deterministic counts** — CPU instructions via Valgrind with `node --predictable`, React commits, style recalcs, DOM mutations — with a **ratchet** that only lowers the ceiling, never raises it. 3,000+ changes, no reported incident *(Anthropic on Anthropic's model improving Anthropic's product — the method is copyable, the magnitude is not independent evidence)*

### Distributed systems at scale

- [Anthropic's Scion — Source Control at Agent Scale](anthropic-scion-source-control.md) — replacing Git when merged changes went 2,500 → 30,000+ a day in four months: the inversion where distribution became the liability because every client was already online, changesets over packfiles so write cost scales with the change rather than the repo, a three-tier cache at 99%+ per tier, and the pre-merge serialisation they gave up to get throughput
- [Airbnb's Database Workload Capture and Replay](airbnb-database-workload-replay.md) — differential testing at the database layer from before the term arrived here: ProxySQL sidecar capture replacing per-language loggers, transactions reassembled and replayed with original timing at a configurable speed factor, MySQL 5.7 as the oracle for 8.0 (one query pattern 0.03s → 2.6s, 273 MB per join instead of 5 MB), and the lesson that pinning `last_insert_id` to make the oracle deterministic removed native auto-increment from the test's scope
- [Zalando's Client-Side Load Balancing](zalando-client-side-load-balancing.md) — moving ~1M req/s off a shared edge load balancer into the calling process: watch-based discovery, consistent hashing with hash parity, occupancy (Little's Law) as the load signal, N-ring fade-in, bounded-load walk, and the cache-locality-vs-zone-cost trade-offs
- [Netflix's Service Topology at Scale](netflix-service-topology.md) — a real-time service dependency graph from millions of flow records/sec: three physical layers, a three-stage aggregation pipeline whose load-bearing step resolves network intermediaries into true application edges, consistent-hashing load distribution against 100x hot nodes, immutable-snapshot time travel, and the cascading-bottleneck lessons
- [Slack AI's Path to Multi-Cloud](slack-ai-multi-cloud.md) — four phases from SageMaker to AWS+GCP: the capacity economics of provisioned vs on-demand throughput and the spillover pattern between them, an intelligent routing layer with circuit breakers and a backup model per feature, the API normalisation layer that is the real price of provider agnosticism, and the operational costs (cost attribution, on-call knowledge gaps) they admit to

### AI code review & PR approval

- [Cloudflare's AI Code Review System](cloudflare-ai-code-review.md) — a production multi-agent review system (131K reviews/month): seven specialised reviewers plus a judge, "What NOT to Flag" negative prompting, risk/model tiering, and the cost/resilience engineering behind it
- [DoorDash's AI Code Reviewer](doordash-ai-code-review.md) — a production AI review agent optimised for precision over recall: the lead-scout→deep-reviewer (notice-then-verify) architecture, company-mined domain review profiles, the three-part false-positive filter and "disprove-it pass", and acceptance rate (not findings count) as the success metric
- [Intercom's AI PR Approval](intercom-ai-pr-approval.md) — AI auto-approving ~19% of PRs with no human reviewer: sub-agents per review dimension, execution-path tracing, accountability moving from reviewer to author, the refusal to approve large changes as the actual safety mechanism, and why the headline 10x revert-rate gap compares the wrong variables
- [Rewind's AI PR Approval Under Compliance](rewind-ai-pr-approval.md) — the second production instance of unattended AI approval (40% of PRs, ~$0.73 each): deterministic gates underneath the model so it judges scope rather than correctness, and controls mappings and risk assessments as the audit-era replacement for a named human approver
- [Rootly Dropped Its Small-PR Rule](rootly-pr-size-risk-labels.md) — retiring a two-year small-PR rule once agents authored 80%+ of the code: risk labels in place of diff-size limits, an AI reviewer that assigns a risk classification rather than style feedback, feature flags moving the safety gate from merge-time to progressive rollout, and a PR template demanding a revert plan

### Agent platforms & harnesses

- [OpenAI's Agent-First Harness](openai-agent-first-harness.md) — five months shipping an internal product with zero manually-written code (~1M lines, ~1,500 PRs, self-reported): agent legibility as the organising principle, the repository as system of record, a ~100-line AGENTS.md table of contents, mechanically-enforced layered architecture, and linters whose error messages carry the fix
- [Uber's MCP Gateway](uber-mcp-gateway.md) — 800+ MCP servers and 5,000+ tools behind a registry/proxy split (control plane and data plane at the agent-tools layer, with in-memory config refresh), governed by **"discovery doesn't imply exposure"** — everything registers disabled and the owning team enables it. Resolves the auto-generated-MCP HOLD in `data-readiness-for-agents`: the objection is to auto-*exposure*, not auto-generation. Plus three context-bloat mechanisms — incremental discovery, GraphQL-like **Response Projection** on replies, and a CLI Code Mode *(Uber on its own platform; all figures are scale, none are outcomes)*
- [Stripe's Kai Agent Platform](stripe-kai-agent-platform.md) — agent skills at production scale: 1,000+ skills from 100+ teams with federated ownership, quality degrading past ~150 skills in context, `allowedTools` gating instead of front-loading 500+ tools, pinned foundational skills for policy consistency, and the sandbox exposed as a tool rather than as the agent's environment *(published by the framework vendor — read the provenance)*
- [Ramp's Inspect Agent Platform](ramp-inspect-agent-platform.md) — an internal coding agent on remote cloud sandboxes rather than laptops, built because local harnesses cap parallel sessions: reported 75% of merged PRs and 1M+ sessions, an existing harness (OpenCode) wrapped in company-built environment and integrations, and the platform effect where a 5.5-person team spawned 200+ custom agents on it *(paywalled after section 3 — the note covers the why, not the architecture; co-authored by Ramp engineers, all figures self-reported)*
- [Migrating the Copilot Runtime to Rust With Agents](github-copilot-rust-migration.md) — the counterweight to this repo's 28-of-520 migration evidence, and an explanation of why it worked: ~430K lines of TypeScript to 832,378 lines of Rust in 128 PRs over 14.5 weeks, with in-place porting keeping the trunk shippable across 135 releases, and temporary interop shims driven from a peak of 2,019 exports to **zero** — migration blindness made impossible to fake. Also the counterintuitive compiler finding (borrow-checker errors just 1.7%; the rest mechanical), a 96.22% prompt-cache hit rate as the economic enabler, and an agent that merged another session's worktree despite four refusals *(GitHub on GitHub using Copilot, but unusually detailed and self-critical)*
- [DoorDash's Multi-Agent Feature-Flag Cleanup](doordash-flag-cleanup-agents.md) — agent work on a task with a *natural* oracle (flag removal should change no behaviour, so builds and tests are a genuine check): 60,000+ flags across ~623 repos, 45 of 50 usable PRs at 13.8 min and $4.79 each, one human checkpoint placed at the judgement (confirm the flag's final value) rather than at review, and a precise account of where deterministic refactoring tools stop — Uber's Piranha failed because DI patterns make the flag/logic relationship "semantic rather than directly represented" *(accepted to the ICSME 2026 industry track, so peer-reviewed; the DoorDash blog 403s to automated retrieval, read via InfoQ)*
- [Cursor's Agent Swarm Economics](cursor-agent-swarm-economics.md) — a frontier planner over cheap workers at similar quality for ~8× less total cost (~23× on the worker fleet), measured on a real oracle: implement the 835-page SQLite manual in Rust with source, tests and internet withheld, graded against sqllogictest. Plus a coordination failure-mode catalogue (split-brain design, ossification, megafiles, review lenses), custom version control at ~1,000 commits/sec, and the finding that 68,000 commits was thrash rather than productivity *(Cursor's own swarm, and the cost-winning worker is Cursor's own model)*
- [Oracle AI Agent Memory](oracle-ai-agent-memory.md) — a governed, unified memory core for AI agents on a single database: the extract→enrich→store→retrieve pipeline, hybrid (vector + keyword + RRF) recall, conversation/session/user/org lifetime layers with TTL, a typed memory graph, and provenance/audit as the enterprise differentiator ("memory with receipts")
- [Slack's Agentic E2E Testing Experiment](slack-agentic-e2e-testing.md) — a measured experiment on where AI agents fit in the E2E testing stack: goal-based vs journey-based testing, three execution models (Playwright MCP / CLI / generated tests) compared across 200+ runs, and the cost/reliability/token trade-offs that put agents at the apex of the pyramid rather than replacing deterministic tests

### Operating models & strategy

- [The Product Engineer Company (Portkey)](portkey-product-engineer-company.md) — Portkey's product-engineer operating model (24 engineers, 0 PMs, 1 designer): end-to-end ownership, the barbell structure, disciplined scope, and how AI factors into reliability-critical infrastructure work
- [Anthropic's AI-Native Team Structure](anthropic-ai-native-teams.md) — two-pizza teams held constant while concurrent projects went from 1–2 to 4–5, so the leverage appears as project parallelism rather than individual throughput; PMs reported as *more* critical, which directly contradicts Portkey's no-PM product-engineer model from the same newsletter *(a single interview, self-described)*
- [Microsoft's AI Strategy — Finding Core Competencies (Nadella)](microsoft-ai-core-competency.md) — a corporate-strategy case study from Satya Nadella's Stratechery interview: core-competency discipline, the hill-climbing machine and private evals as moat, three-bucket capital allocation, token capital, consumption pricing, and model/harness independence
